# AEGIS V5.4 — Download Test Strategy

## Selected strategy: Preference 3 — programmatic in-container test of the SAME export functions

### Why not Preference 1 (UI browser automation)
The dashboard is reachable at `http://127.0.0.1:8080`, so UI automation is
technically possible. However, each download requires: click an assistant →
generate → open the download modal → click a per-format download link whose URL
is a per-session Shiny download token. Driving that reliably adds significant
harness complexity and session-token handling, and it validates the *click*
path, not additional file-generation logic.

### Why not Preference 2 (raw HTTP endpoint)
Shiny `downloadHandler` endpoints are session-scoped (require an active
websocket session + token); invoking them out-of-band is brittle and not more
faithful than calling the underlying functions.

### Chosen: Preference 3 (programmatic, in-container)
A small R harness (`_render_harness.R`) was executed **inside the running
container** (`docker exec ... Rscript`). It sources the real app (`global.R`)
and calls the **exact same functions the Shiny download handlers call**:

- Explanation: `.llm_build_markdown` / `.llm_build_txt` / `.llm_build_html`
  and `.llm_render_export(md, file, 'docx'|'pdf')`.
- Governed: `file.copy` (verbatim CSV), `.artifact_build_md/_txt/_html`, and
  `.llm_render_export(...)` for DOCX/PDF.

This exercises the true Docker export toolchain (pandoc, TinyTeX/LaTeX, UTF-8,
fonts, tempfile in `/tmp`, read-only mounts) — which is exactly what V5.4 must
prove. It validates the **file-generation path**, not the browser click.

### Honesty / limitations
- This is a **programmatic** test, NOT a UI click test. Documented as such.
- The download handlers in `server.R` wrap these exact functions in
  `downloadHandler(content=function(file){ ... writeLines/file.copy/.llm_render_export ... })`,
  so the generated bytes are identical to what a user download would stream.
- No app logic was changed to make testing easier.

### Evidence
- Generated files copied out via `docker cp` to
  `outputs/v5_4_dockerized_downloads_validation/download_samples/{explanation,governed}/`.
- Signatures validated on host (%PDF, PK zip + `[Content_Types].xml`,
  `<!doctype`, UTF-8, SHA256 for verbatim CSV).
